# RAPP Work: mandatory RAPP/1 integration contract

RAPP Work is a **derived UI**, not another event, audit, approval, VM lifecycle,
or workspace-history store. All durable facts represented as verified Work
must be canonical eleven-key `rapp/1` frames. There are no new frame kinds,
hash domains, identity schemes, or parallel JSON event logs in this contract.

This branch owns **verification and an exact integration contract only**.
It does not implement frame persistence, VM commands, or the gateway adapters
described below. An unintegrated gateway returns method-unavailable; the UI
then labels data unverified and blocks Work mutations. Compatibility tools
remain available but are explicitly **not certified** as RAPP/1 history.

## Authority and shared implementation

The selected authority is the repository-owned immutable
`ACCEPTED_RAPP_PROTOCOL_AUTHORITY`, currently **rev-14**:

| Binding | Value |
| --- | --- |
| Checkpoint | `caf6ef276cafa92aa744499af90dc1a28559941a` |
| Authority frame hash | `59629adab4e26d156f3d66ecfb766e08705919ea1d2adc92ba0ad2b17337dfc2` |
| Authority payload hash | `c7549bbd3e133b833930e24e008817ea295734b870f41706455d3f45821aba3a` |

The executable contract is
[`work-contract.ts`](../typescript/src/rapp/work-contract.ts). The persistence
owner uses [`work-verification.ts`](../typescript/src/rapp/work-verification.ts)
with the existing production `verifyRappFrameJson` / `verifyRappFrameChain`
scanner. Trusted genesis and persisted heads are supplied through
**module-owned `RappChainTrustPolicy` selections from the trusted store**,
never copied from RPC input or inferred from a frame's own claims.
`WorkFrameSelection.subject` must match the authenticated resource lookup;
both stream policies must belong to that resource's authorized producer.

Node and browser share the extracted canonical JSON, frame preimage,
stream-family, timestamp, and evidence-payload definitions. Existing imports
remain compatible. The browser uses Web Crypto with those same canonical
bytes; it does not introduce a second serialization or addressing scheme.

## Durable fact mapping

Application data belongs **inside** the canonical frame payload. The DTOs
used to lay out the screen are ephemeral projections, not a persistence format.

| Work scope | Source frame kind | Evidence application event |
| --- | --- | --- |
| Agent snapshot | `memory.save` | `agent.snapshot` |
| Workspace state/history | `memory.save` | `workspace.snapshot` |
| Task state | `memory.save` | `task.changed` |
| Run/tool receipt | `memory.tool-call` | `run.recorded` |
| Committed chat message | `memory.chat-turn` | `chat.recorded` |
| Citation/source projection | `memory.save` | `evidence.recorded` |
| Pending approval | `memory.save` | `approval.pending` |
| Approval decision | `memory.tool-call` | `approval.decided` / `approval.failed` |
| Observed VM state transition | `memory.save` | `vm.snapshot` |
| VM start/stop outcome | `memory.tool-call` | `vm.started`, `vm.stopped`, `vm.start-failed`, `vm.stop-failed` |

The source is on the responsible producer's **memory stream**, e.g.
`rappid:@owner/name:<64-hex>:work`. Its linked evidence is a `body.pulse` on
that same producer's **bare RAPPID body stream**. Local Work does not emit
swarm telemetry; swarm streams require their dedicated signature policy and
are refused by this unsigned-local integration.

Live presence, progress notifications, connection indicators, and refresh
timestamps are hints, not durable history. A producer must append any durable
transition before publishing its projection. Polling itself must not append a
new history record. The UI never promotes an unscanned chat/VM notification
into a verified event.

### Payloads and hashes

A normal source payload has exactly:

```text
{ subject, data, protocol_revision }
```

`data` is the exact JSON projection being displayed, not a success flag or
unverified summary. `subject` is generated by `workSubject(scope, ...ids)`;
each resource ID is percent-encoded and multi-part IDs are slash-separated.
`protocol_revision` is the existing three-field selected authority identity:
`{ revision, frame_hash, payload_hash }`.

The evidence payload reuses **`openrappter-evidence/1`** unchanged, via
`buildRappEvidenceFrame`:

```text
{ schema, event_kind, subject, data_hash, reference_hashes, protocol_revision }
```

`data_hash` is `H("rapp/1:particle", data)`. `reference_hashes` is sorted and
deduplicated and includes both the source **payload hash** (particle domain)
and **frame hash** (wave domain). This binds the exact occurrence even when a
state value recurs. Action outcomes also reference the request particle and
both the accepted intent's particle and wave hashes. Replaying the identical
evidence particle is refused under the existing evidence profile.

Every frame retains the canonical keys:
`spec`, `kind`, `stream_id`, `seq`, `utc`, `payload`, `payload_hash`,
`frame_hash`, `prev`, `prev_wave`, `sig`. Particle and wave hashes use the
existing domains and RFC 8785 canonical bytes. The wave preimage excludes
**both `frame_hash` and `sig`**. On these local body/memory streams,
`prev` links the predecessor **payload hash**, `prev_wave` is null, and
`sig` is null. Sequence, UTC ordering, family, selected authority, trusted
genesis, forks, and the store-selected committed head must all pass scanning.

## Read adapter: `work.rapp.verify`

Request: exactly `WorkProjectionClaim`:

```text
{ scope, subject, data }
```

Response: exactly `WorkRappScan`:

```text
{
  body:   { ok: true, frames, head, trust },
  memory: { ok: true, frames, head, trust },
  source_frame_hash,
  evidence_frame_hash
}
```

Each chain is the existing canonical scanner result, not an alternate audit
envelope. Referenced source/evidence frames must actually occur in the chains,
bind this subject/data/event, and not be superseded by a later subject frame.
The head must match the store-selected **committed** head, not an unpersisted
extension. Raw frame bytes passed to `scanWorkProjection` must be exact
canonical JSON; whitespace repair, partial chains, and trust-by-filename are
not accepted.

The gateway must resolve already-persisted records independently. **Never
mint a verified frame or select a genesis merely because the UI submitted
a claim.** If no evidence exists, refuse the claim. Missing adapters, invalid
proofs, and unavailable Web Crypto remain visibly unverified/invalid.

Proof streams must already be authorized for the renderer. Prepare redacted,
canonical projection frames before publication; never remove private fields
from an existing hashed frame and call the result verified. Keep raw recording
paths, credentials, and private execution IO out of renderer-visible streams.
References to private source particles do not certify their unseen contents.

The UI independently checks frame key sets, registered families, timestamps,
sequence, links, hashes, source/data binding, and authority. It tracks observed
heads in memory to detect rollback/forks. It trusts the authenticated gateway
for the store's genesis and durable-head selection; a hash cannot prove an
`fsync` or establish producer identity. Proofs exceeding the shared 1 MiB
canonical input bound are refused, never truncated into verified evidence.

## Mutation adapter: `work.rapp.commit`

Request: exactly `WorkCommitRequest`:

```text
{
  method: "vm.start" | "vm.stop" | "exec.respond",
  subject,
  params,
  basis: {
    protocol_revision,
    body: RappFrameHead,
    memory: RappFrameHead,
    source_frame_hash,
    evidence_frame_hash
  }
}
```

VM params are `{}` and the subject is `vm:omarchy`. Approval params are exactly
`{ approvalId, approved: boolean }`; the subject must name that approval.
The UI never calls the unguarded legacy mutation methods as a fallback.

The persistence owner must implement this order:

1. Authenticate and validate method availability and authorization. Resolve and
   scan the current records with store-owned trust selections.
2. Call `assertWorkCommitPrecondition` on a **real locally minted scan**. Compare
   both heads and both referenced frames atomically; reject stale state before
   acting. Require a local Omarchy stopped/running state for start/stop, or the
   unchanged pending, unexpired approval. Recheck expiry with the server clock.
3. Deduplicate by `H("rapp/1:particle", request)`. A retry returns the existing
   canonical outcome and frame IDs, never a second execution.
4. Durably append exactly one accepted **write-ahead `memory.tool-call`** intent
   before invoking the operation. Its payload is exactly
   `{ subject, data: { phase: "accepted" }, protocol_revision, request }`.
   If the append fails, do not execute.
5. Execute once under the gateway's existing consent/security boundary. Append
   the terminal `memory.tool-call` payload
   `{ subject, data, protocol_revision, request, outcome, error }`.
   `outcome` is `success` or `error`; `error` is null for success and a nonempty
   string for failure. Failed actions are framed failures, never fabricated
   successful state changes.
6. Append the linked canonical `body.pulse` evidence, referencing the request
   particle plus the intent/terminal particles and waves. Commit the durable heads, rescan, and only
   then publish the RPC response or durable notification.

Response: exactly `{ data, scan }`. `scanWorkCommit` checks the exact request,
predecessor lineage, one referenced intent, terminal outcome, and data binding.
The UI advances state only after independently checking that receipt. A failed
operation can carry verified failure evidence without being presented as a
successful VM/approval change. Missing or invalid receipts leave the outcome
unconfirmed; do not automatically retry an operation that might have run.

## UI verification language

Every relevant Work surface includes a RAPP/1 status: **unverified**,
**adapter unavailable**, **verification failed**, or **verified integrity**.
Only the local verification path can mint a verified badge; wire booleans,
lookalike receipt objects, filenames, and method success are insufficient.

Unsigned local integrity is **not promotion-grade**, a signature, independent
source verification, proof of sandbox enforcement, or blanket product
compliance. Demo records have no canonical frames and are labeled unverified
demo; they are never persisted. The local VM iframe is view-only, so it cannot
bypass the canonical command boundary.

## Evidence and tests

`work-rapp-contract.test.ts` scans the real pinned rev-14 authority fixture
and independently recomputes its particle/wave hashes. It also scans full
canonical fixture streams, checks every scope, write-ahead intent, idempotent
retry and framed failure, and rejects authority, family, payload, lineage,
head, projection, and request substitution. Existing canonical scanner tests
remain unchanged and passing.

Component tests exercise verified and unavailable/invalid badges and disabled
mutation controls. The production browser check uses the same canonical
in-memory fixture builder and real scanner, then verifies those bytes with
browser Web Crypto. **That fixture is test-only and must not be reused as a
production persistence adapter.** No real VM command or frame-store write is
performed by these UI checks.
