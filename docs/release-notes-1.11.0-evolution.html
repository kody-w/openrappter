WHY THIS RELEASE MATTERS

A pin nobody checks is only a claim about the past.

📌

The Copilot CLI ships with the commit

OpenRappter reasons through the GitHub Copilot CLI. Until now it was found by searching machine-wide paths, so its version was decided by whoever last ran copilot update. It is now a lockfile-pinned dependency installed into the source tree by npm ci.

🔍

Resolution order is asserted, not incidental

An explicit operator override still wins, then the pinned copy, then the ambient globals. The order is covered by tests, because a resolver that merely can find the pinned binary while still letting a global win has changed nothing.

🧾

The digest is re-checked before reuse

The installer stamps the CLI's SHA-256 at build time and verifies it again before reusing an installation, so a binary substituted after install triggers a rebuild instead of being executed.

🪪

Status stopped misreporting

--status judged Copilot solely by GITHUB_TOKEN, so it reported Copilot unavailable while the gateway answered happily through the CLI backend, which carries its own credential. It now names the binary that will actually answer.

🔗

Releases are verifiable before execution

Installer digests are computed from the commit's git blob rather than the working tree, so a stale checkout or a local line-ending conversion cannot publish a hash for bytes that were never released.

🤖

Everything is drivable without the UI

One documented HTTP wire, JSON-RPC on the same port, and a headless CLI. A capability that can only be exercised by clicking is a capability that cannot be tested.

WHAT CHANGED

Pin it, prove it, then let it answer.

PIN

Local-repo dependency

@github/copilot is a lockfile dependency, resolved from this package's own node_modules rather than from PATH.

ANCHOR

Resolved from the module

Anchored to the module's own location, not process.cwd() — the daemon is frequently started from somewhere else entirely.

STAMP

Digest recorded

The installer writes the CLI's SHA-256 into the install and into .rapp-install.json provenance.

VERIFY

Checked before reuse

A changed binary invalidates the install and forces a rebuild rather than being run.
